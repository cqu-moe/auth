# 敏感账号操作要求五分钟内的身份验证

修改密码、更换邮箱、关闭或更换二次验证、查看恢复码，统一要求最近五分钟内完成身份验证。已启用二次验证的账号还须通过二次验证；邮箱验证码不能直接绕过已有二次验证。这样可复用近期验证结果，同时限制被窃取的普通会话执行敏感操作。

近期验证以真正完成身份验证为依据，不把会话自动续期当成重新验证。具体因子组合与证明保存方式优先使用框架原生能力。

二次验证丢失时优先使用恢复码；材料全部丢失时由具备对应管理权限、已完成强认证的管理员执行一次人工重置。旧密码、Passkey、TOTP、恢复码、信任设备、旧设备访问及未完成的旧认证流程全部作废，系统生成随机新密码并一次性返回供管理员交付用户。只保存密码哈希，不在日志或审计中保留新密码明文。

用户以新密码正常登录，之后按需配置认证方式；不另设受限恢复、强制重建因子或首次强制改密流程。管理员账号仍需满足管理功能的强认证要求。普通忘记密码保留原 Passkey 与二次验证；两种恢复方式都保留学校绑定、业务权益和后台同步。

取消邮箱验证码作为登录第二因子的替代路径。邮箱验证码用于邮箱验证和密码找回，不替代 TOTP、恢复码或经用户验证的 Passkey；密码找回不能解除账号已有的二次验证。

此处的邮箱第二因子专指 Auth 的中央账号认证，不包括学校 CQU 邮件验证码的接收和处理；学校侧登录链路继续保留。

本轮新增 Passkey。经服务端确认完成用户验证的 Passkey 可独立满足上述强认证要求，无需叠加密码或 TOTP，见 [Passkey 认证规则](./0008-passkey-authentication.md)。使用密码路径时，已有二次验证仍需满足；添加和删除 Passkey 的门禁与具体证明实现须在方案中统一。

管理员和超级管理员进入管理功能前，必须完成经用户验证的 Passkey，或密码加 TOTP/恢复码。尚未配置的管理员可以先进入自己的安全设置完成绑定，不能凭管理员角色跳过认证要求；普通用户的二次验证保持可选。

信任设备可以用于普通登录便利，但不构成五分钟内真实完成强认证的证明，也不能单独满足管理员强认证要求。前端页面、业务接口与 Better Auth 原生敏感端点执行一致的后端策略。

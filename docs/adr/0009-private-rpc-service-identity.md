# 用户 OAuth 与私有 Worker RPC 服务身份并存

浏览器、插件及适用的外部客户端继续使用用户 OAuth 凭据；第一方 Worker 后台通过 Cloudflare Service Binding RPC 使用服务身份和目标 userId。现有后台课表同步不强制迁移成逐用户 refresh token，也不增加为此服务的令牌存储、轮换与恢复体系。

服务身份只用于私有 Worker RPC，不新增等价的公网“服务身份加任意 userId”入口。复用现有调用方身份与服务器侧权限配置，由 Auth 统一检查调用方是否获准执行该业务操作，以及目标用户的当前状态、业务权益和学校绑定；RPC 私有性不能代替这些检查。对外 HTTP 请求不能通过转发任意 userId 借用后台权限。

两种身份的用途明确分开：服务身份不是某个用户的登录会话，不能凭它修改中央账号安全设置或取得该用户的通用登录身份。后台同步不受设备退出、改密和账号恢复影响，账号封禁或学校解绑仍终止相应访问。

## 取舍

同步 Worker 本来就有访问全部符合业务条件用户的职责。若该 Worker 整体失陷，把同一批用户的 refresh token 集中存放在其中，不能形成显著的新隔离层；私有 RPC 又使外部攻击者不能仅凭泄露的服务密钥直接调用该入口。因此本次优先减少凭据状态和迁移成本。

逐用户凭据仍能限制单个用户凭据泄露或错绑的影响，但该收益不足以支撑本次后台同步迁移。已获准的 Worker 或其调用链被攻破时，服务身份影响范围覆盖该服务被授权访问的用户；此风险通过限定业务操作、集中权限检查和调用审计约束，不以“走 RPC”作为绝对安全保证。

## Parent

[Auth 安全与第一方接入升级 #41](https://github.com/cqu-moe/auth/issues/41)

## What to build

让用户实际完成密码与现有二次验证后，能够在五分钟内操作安全设置；普通会话和信任设备不能冒充近期认证。同步收紧管理员准入和邮箱验证码边界。复用现有页面与后端入口，不另造通用认证平台。

## Acceptance criteria

- [ ] 提供可用的再次验证交互与服务端证明；证明绑定当前用户、会话、用途和五分钟有效期，挑战单次消费，错误账号/会话、过期及重放均被拒。
- [ ] 密码路径遵守账号的 TOTP/恢复码要求；未开启 MFA 的普通用户可以用现有密码完成验证，信任设备和 session 自动续期不产生强认证证明。
- [ ] 改密码、换邮箱、关闭/替换 MFA 和恢复码管理都经过共同后端门禁；直接调用 Better Auth 原生端点不能绕过页面验证。
- [ ] 管理员及超级管理员只有实际完成强认证才能使用管理功能；尚未配置者能先完成自己的安全设置，原有角色及目标用户权限层级不被放宽。
- [ ] 取消 Auth 邮箱验证码作为第二因子的发送、验证与 UI 替代路径；邮箱验证/密码找回保持可用，不能越级自动登录或解除已有 MFA。
- [ ] 学校 CQU 邮件验证码处理与登录链路保持不变；恢复码的并发单次使用得到真实存储测试覆盖。
- [ ] HTTP 集成覆盖门禁与有效证明，浏览器覆盖一次验证后继续原操作；不增加专用于测试的生产接口。Passkey 的强认证接入由后续票扩展同一规则。

## Parent

[Auth 安全与第一方接入升级 #41](https://github.com/cqu-moe/auth/issues/41)

## What to build

让“退出全部设备”、正常改密和普通密码找回真正终止对应设备的会话与续发能力，同时保留私有 RPC 后台课表同步。向第一方应用提供可消费、可验证的退出及权威状态契约，为后续独立应用会话迁移做好准备。

## Acceptance criteria

- [ ] 用户可在现有设置中结束设备访问；全设备退出撤销相关 session、设备 access/refresh 续发能力及适用的设备信任，设备 offline_access 不能逃过注销。
- [ ] 正常改密保留当前已验证会话、结束其他设备访问；普通密码找回结束旧设备访问，但保留已有 Passkey/MFA，重新登录仍须满足它们。
- [ ] 退出、改密和找回均不删除后台服务身份、学校绑定、业务权益或已启用的同步配置。
- [ ] 复用原生令牌状态能力及现有权威数据。普通受保护读取最多六十秒失效，敏感操作和学校登录能力在下一请求检查最新状态；不假定 JWT 必有持久 access-token 行。
- [ ] 提供给应用的中央会话/授权关联和注销契约能覆盖漏收通知；权威校验不可用时不能无限保留旧允许结果，高风险访问失败关闭。
- [ ] HTTP/设备流程验证注销后的旧 access 与 refresh 均不可继续使用，并验证未撤销用户和后台 RPC 正常工作。
- [ ] 复用既有 #36 对“用户封禁/应用禁用后存量令牌仍可铸票”的修复，本票不重复创建该漏洞；新增的是设备生命周期、事件范围和第一方退出契约。

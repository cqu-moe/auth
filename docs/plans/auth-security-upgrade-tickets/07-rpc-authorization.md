## Parent

[Auth 安全与第一方接入升级 #41](https://github.com/cqu-moe/auth/issues/41)

## What to build

保留第一方 Worker 的服务身份加 userId 调用方式，在 Auth 的私有 RPC 入口集中执行必要的业务授权，使课表后台继续工作，同时拒绝未获准服务、用户和操作。复用现有身份及权限状态，不创建后台逐用户 refresh token 系统。

## Acceptance criteria

- [ ] 继续验证服务凭据及应用启用状态，不能仅相信 caller 自报 clientId 或拥有 Service Binding；按实际 RPC 方法检查获批能力。
- [ ] 权益查询、学校取票和采集分别检查该操作需要的用户状态、业务权益、学校绑定和目标范围，不向无关方法添加学校绑定要求。
- [ ] 通用采集也由 Auth 执行授权检查，不只依赖调用方；服务身份不能用于中央账号安全管理或取得通用用户登录身份。
- [ ] 只保留私有 RPC 通道，不新建等价公网入口；核查相关公开调用链不能无条件转发外部指定的任意 userId 借用后台权限。
- [ ] 保留现有 CQU 会话控制、目标主机、限流和审计入口，记录服务、目标用户与操作；不绕开既有取票/采集控制点。
- [ ] 通过真实鉴权和测试 D1 验证合法服务可调用，错误 secret、禁用应用、封禁用户、权限不足或无有效学校绑定的相关请求被拒；不能把鉴权 mock 成始终成功。
- [ ] 浏览器退出、改密和密码找回不影响合法后台调用；学校解绑的一致性修复继续由既有 #37 承担，最终联合验收覆盖它，不重写学校登录状态机。

## Parent

[Auth 安全与第一方接入升级 #41](https://github.com/cqu-moe/auth/issues/41)

## What to build

完成 Schedule 第一方 Web 的 OAuth/OIDC 登录与独立应用会话迁移：用户可以从中央登录进入课表、单站退出并主动接回；后台课表同步继续使用私有 RPC。该票涉及现行 Schedule 接入及必要的 Auth 配置，不只交付接入文档。

## Acceptance criteria

- [ ] 核实当前使用的 Schedule 部署和客户端配置，使用已有后端完成授权码/PKCE 交换，建立本站 host-only、Secure、HttpOnly 会话；浏览器不持有长期 refresh token。
- [ ] Schedule 默认向用户开放，无逐应用开通或同意步骤；管理员业务权益对使用资格、功能和额度的控制生效，不放宽对象归属及其他业务权限。
- [ ] 单站退出只结束本站会话并停留在退出页面；用户主动登录时复用中央登录，其他站点不会被一并退出。
- [ ] 本站会话消费 T04 的权威状态与退出契约，中央全设备退出、用户封禁和应用禁用生效；漏收通知也不能超过六十秒继续受保护读取。
- [ ] 后台同步继续按 T07 的服务身份调用，不保存逐用户后台 refresh token；改密、恢复、设备退出不清除用户同步配置。
- [ ] 完成浏览器端到端及服务集成验证，覆盖登录回跳、Cookie 隔离、权益控制、单站退出与后台继续，并更新实际接入说明。
- [ ] 按先接入后收口的顺序迁移，不在 UC 等现存消费者尚未准备好时全局移除旧中央 Cookie；最终切换由 T10 完成。

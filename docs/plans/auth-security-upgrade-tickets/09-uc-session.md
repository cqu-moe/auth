## Parent

[Auth 安全与第一方接入升级 #41](https://github.com/cqu-moe/auth/issues/41)

## What to build

完成 UC 当前在用版本的中央登录与独立应用会话接入，让 UC 不再依赖收到 Auth 的根域 Cookie。保留 UC 原有成员、资源和文件权限。先核定现行部署与代码归属，不能仅因本地存在旧仓库就改造退役版本。

## Acceptance criteria

- [ ] 确认 uc.cqu.moe 当前使用的实现与 Auth 接入，针对在用代码迁移；若已具备目标协议，提供实际验证而不是重复改造。
- [ ] 通过现有后端完成 OAuth/OIDC Code + S256 PKCE，验证 issuer、事务和用户身份，建立 UC 自己的 host-only、Secure、HttpOnly 会话。
- [ ] 第一方登录默认授权，无用户逐应用开通步骤；中央身份不自动替代 UC 的成员资格、对象归属和文件权限，既有业务数据保留。
- [ ] 单站退出只影响 UC 并停留在退出页面；主动登录可接回；消费 T04 的退出/状态契约，漏收通知仍满足撤销时限，高风险验证失败不放行。
- [ ] 浏览器及集成测试验证登录、受保护资源访问、单站退出、中央全设备退出和依赖不可用场景，不将后端角色/资格检查搬到前端。
- [ ] 更新实际接入配置与文档；本票不改造 UC 的内容系统、不新建 BFF 服务，也不提前切断其他应用仍需要的中央 Cookie 兼容。

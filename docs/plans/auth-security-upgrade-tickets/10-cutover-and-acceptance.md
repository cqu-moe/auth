## Parent

[Auth 安全与第一方接入升级 #41](https://github.com/cqu-moe/auth/issues/41)

## What to build

在消费者适配后完成中央 host-only Cookie 收口、移除旧根域 Cookie 依赖，交付可执行的迁移/回滚说明与整条认证链路的联合验收。此票交付真实的最终隔离行为，不只重新跑一遍已有测试。

## Acceptance criteria

- [ ] 以实际接入清单确认所有使用旧共享 Cookie 的在用消费者已迁移或退役；Schedule、UC 与 QuickLogin 的真实接入状态有证据，不能把本地目录或通用示例当生产清单。
- [ ] 中央 Cookie 仅属于 Auth，旧根域 Cookie 被清理且不能继续充当通用中央凭据；可信来源按需要收紧，CSRF/来源防护与既有正式端点保持正确。
- [ ] 跨应用验证单站退出、全设备退出、正常改密、找回与管理员随机密码重置：对应设备访问失效，既有后台同步继续；无 MFA 的管理员只能配置自身安全方式，不能进入管理功能。
- [ ] 联合验证既有 #36 的存量令牌拒绝，以及 #37 在 D1/DO 清理失败时的解绑效果；不能在清理未完成时宣称解绑成功，也不能让后台继续绕过封禁或解绑。
- [ ] 验证可选 DPoP 与普通 Bearer、Passkey、近期认证和撤销策略的组合；并发/多实例及失效边界有证据，不把 token 验签或一次通知当作完整撤销。
- [ ] 迁移保留账号、学校绑定、权益和必要客户端数据，明确可接受的重新登录与临时流程重启；有预检、失败处理、回滚或向前修复条件，沿用手写 SQL 迁移。
- [ ] 更新受影响的协议文档、接入指引和生成契约；API/MCP 仅保留清楚的身份与权限概念，不交付网关、工具、占位代码或新授权系统。
- [ ] 分别记录自动测试、构建/类型检查、部署准备与真实浏览器/插件验收；若生产尚未获授权，仅报告测试环境和准备结果，不冒称已上线。

# Schedule 新用户动线与首次同步：确认规格

状态：用户已确认动线和第二版预览。本文约束后续实施，不代表功能已上线。

## 1. 最终用户动线

Schedule「开始使用」→ Auth 登录或注册 → 必要的邮箱验证与二次验证 → 绑定重庆大学统一认证账号 → 绑定成功 → 自动返回 Schedule → 为符合现有权限的新用户自动创建三个个人订阅并同步 → 使用现有订阅卡片复制链接。

登录、注册、验证和绑定在 Auth 内连续完成。禁止注册后先回 Schedule，再去 Auth 绑定。
已登录或已绑定的步骤跳过。直接访问账号中心不强制跳课表。

## 3. 自动订阅的确定规则

固定三种：`personal_all` / 我的全部课表；`personal_courses` / 我的课程；`personal_exams` / 我的考试。全部使用认证会话 user.id 作为 user_id 和 source_id，不信任客户端身份字段。

服务端检查现有 `caps.calendar.sync` 和 `sub_limit`，无新增权益接口、不修改权益、不增加注册字段。无 sync 权限返回 skipped，正常结束接续，不展示新的权益开通页面。
有权限且初始状态无任何订阅、无初始化记录的账号，一次事务创建三条订阅、三条默认链接和一条账号级初始化记录。额度不足以容纳三条时整批不创建，返回既有 `QUOTA_EXCEEDED`；不绕过额度，不擅自降级成只建一条。
有历史订阅的账号记录 existing 并保持原样。初始化已完成的账号重复进入不补删掉的订阅、不旋转链接。所有后续删除操作持久化 existing 记录后再删除，防止删空后被误当新人。

自动初始化只由主动的服务接续入口触发（URL `setup=1`）；普通 GET、后台任务、老用户打开仪表盘不凭空创建订阅。上线迁移为仍有订阅的用户写入 existing 标记。上线前已删光全部订阅且不留历史记录的账号无法仅凭空列表识别；不后台猜测、不批量补齐，该账号只有主动重新走「开始使用」才可能执行第一次初始化。不得声称系统能恢复不存在的历史。

初始化完成记录与同步是否成功分开。一次正常初始化只向 Queue 发送一条同 run_id 的个人同步消息，现有消费者把一次抓取写入三份视图。Queue 仍是至少一次投递，不能承诺物理上的 exactly-once。

## 4. Auth 接续与绑定

直接进入现有 `/cqu/bind?redirect=<最终服务地址>`。未登录时 ProtectedRoute 把这整个本地路径作为登录 redirect；验证后回到绑定路径，不提前跳到它内层的服务地址。
统一认证账号的固定名称为「重庆大学统一认证账号」。登录来源短提示为「继续使用重庆大学课表」。不重做登录、注册、2FA 表单。

绑定页刷新先查真实状态。凭证优先判断（已完成本地修复）；无记录不等于查询失败。新凭证在首次登录完成前必须为 pending，防止刷新时把尚未完成的绑定当成功。显式重新绑定使用repair=1，仅用于阻止已绑定账号自动跳过修复，不构成任何权限。已有 active 老账号不因缺邮箱记录被要求重绑。
默认绑定目标只接受经过校验的第一方服务地址；不得返回绑定/登录循环。不把密码、验证码、Cookie、登录令牌放进 URL、storage、日志或设计预览。

成功页：
- 标题「绑定成功」；正文「可以返回使用服务了。」
- Schedule 来源主按钮「返回课表」，3 秒自动返回；「留在此页」取消倒计时。
- 其他合法第一方来源主按钮「返回服务」。
- 独立进入账号中心：不自动跳，提供「前往课表」和「返回账户设置」。
- 真正成功才显示成功；pending、网络错误、无效响应都不能显示绿色完成或启动倒计时。

学校按钮固定：`https://self.cqu.edu.cn/cas-success/safe-center/email-bind-way/rebind`，文字「前往修改密保邮箱」，`target="_blank" rel="noopener noreferrer"`，辅助句「发送验证邮件后，回到这里查看验证码。」。该链接是用户提供的，未通过登录态实测学校修改流程。转发模式不要求用户更换密保邮箱。

## 5. 异常和旧功能

保留邮箱验证、二次验证、密码找回的原验证强度和 native Better Auth 流程。验证链接在另一个标签打开后，原页 focus/visibility 恢复时重新查询会话，再沿原目标继续。
绑定刷新恢复只持久化当前用户、绑定地址、方式和步骤；没有密码或验证码。以服务端状态为准，storage 不可用时回到可安全继续的步骤。
同步轮询复用现有 3 秒轮询、429 退避、run_id 防旧结果覆盖和超时逻辑，禁止另起并行无限轮询。
普通手动刷新依旧遵守 manual_refresh 与冷却。用户已有课表时刷新中仍可使用旧的有效链接；仅首次没有数据的订阅禁用复制/二维码/网页预览。
共享链接、下载、删除、通知开关、外部订阅软禁用、权限和现有 API 格式必须保留。

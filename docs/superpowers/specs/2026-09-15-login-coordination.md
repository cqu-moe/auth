# 登录协调、会话恢复与课表重试

本设计同时覆盖 Auth 和 Schedule。目标是部署或请求中断后能够确认旧任务已停止、恢复账号通道，并让课表同步继续等待恢复；不能把风控、容量不足或暂时失效误报为密码错误。

## 职责

- `CquSessionDO` 是每个账号的状态、CAS 锁、QuickLogin 设备锁和验证码 FIFO 通道的权威。状态变更使用存储事务；网络调用在事务和初始化屏障之外执行。
- `CquSessionRecoveryWorkflow` 持久化恢复检查和等待步骤。每个账号一次恢复周期最多 30 分钟；实例 ID、截止时间、创建确认在 DO 中持久化。创建丢失回执时查询原实例；结束但未完成清理的实例按同一截止时间重建。Workflow 不保存密码、Cookie 或验证码，不重试整段 `/run`。
- Container 执行浏览器任务。每个 token 在同一 boot 中只能启动一次。`/login-cancel` 的 `stopped:true` 只在实际任务及清理完成后返回；`mayHaveRequestedCode` 记录是否已经获得发码许可。取消前到达、重复取消、完成后重放均由保留 40 分钟的终态记录处理。
- Schedule Queue 保存同步 runId、原始请求时间和会话恢复重试次数。等待或失败只更新同步状态，不覆盖已有 ICS、课程和考试数据。

## 阶段与中断

| 阶段 | 正常推进 | 中断后处理 |
| --- | --- | --- |
| 获取任务锁 | 原子保存 token、路由和 13 分钟操作截止时间 | 新请求不能按 TTL 抢占尚未确认结束的锁 |
| 容器准备 | 探测 boot，写回准确路由 | v1 路由尚无 boot 时可确认尚未启动；其他旧格式缺失不作停止证明 |
| 排队与发码许可 | 同一账号仅一个 owner；FIFO 变更先落盘，再重放 outbox | 启动时捕获所有 CAS、QuickLogin 和仅有租约的失去执行者的任务；不向失去执行者的队列项发许可 |
| 发码前取消 | Container 确认 stopped 且未领取发码许可 | 删除对应任务锁并交接通道 |
| 发码后取消或失败 | Container 确认 stopped 且可能已请求验证码 | 任务锁立即删除，验证码通道独立隔离；保留原有有效期，邮件未到时从确认停止起保守隔离 10 分钟 |
| 收到验证码 | 只投递给权威 owner，保留接收时间 | 重启、轮询不重新开始隔离计时 |
| 登录成功 | CAS 会话和状态原子提交；QuickLogin 成功缓存核对绑定 epoch | 旧 token、旧 epoch、旧设备 generation 的迟到结果不能覆盖新状态 |
| 解绑、换绑、撤销 | 立即改变绑定权威状态并移除凭据或关闭会话 | 保留非敏感取消路由和恢复记录，确认外部任务停止后清理 |

操作执行期限、验证码隔离期限、终态 token 保留期限分别管理。39 分钟常量只保留为旧记录迁移的保守上界；新任务使用明确的操作截止时间和取消确认。没有路由的旧记录不能安全推断浏览器已停止，必须保持隔离直到保守期限。

## 失效、风控与重试

- 已确认失效：返回 `SESSION_INACTIVE` 或 `TGT_EXPIRED`，启动账号恢复周期。DO alarm 发起单次重登；已有任务时只等待，不运行第二次保活或登录浏览器。
- 网络、瑞数、发码失败、容器繁忙：不清掉已有会话，不累计为密码错误；持久化 60、120、300、600 秒、最多 900 秒的登录退避。请求轮询不能重置退避。自动 CAS 重登仍受每小时最多 6 次的后备限频约束。
- 明确凭据拒绝：按已有连续凭据失败策略进入 `needs_reauth`，自动恢复结束；用户需要处理认证问题。
- Workflow 超出周期：结束本轮，保留原会话数据并冷却。不会无限延长同一周期。所有时间分支均在持久化 step 内决定，重放复用已有结果。
- DO 的一个 alarm 同时服务保活、任务截止、取消重试、验证码隔离和 Workflow 创建/状态检查，取所有维护截止时间的最早值，保活不能推迟锁恢复。

## 课表行为

| Auth 结果 | Schedule 行为 |
| --- | --- |
| 正常 | 采集完成后，在同一 runId 的所有权校验下更新数据 |
| `SESSION_INACTIVE` / `TGT_EXPIRED` | 在原始同步请求起 30 分钟内等待恢复；会话恢复单独计次，最多 12 次，延迟为 60、120、300 秒后保持 300 秒 |
| `NEEDS_REAUTH` | 结束自动重试，提示重新认证 |
| WAF / 网络 / 采集阶段暂时错误 | 保留已有有限重试策略；不提示密码错误或重新绑定 |
| 浏览器容量不足 | 保留容量等待策略，其次数不能消耗会话恢复专用次数 |
| 恢复窗口耗尽 | 结束本次同步，明确提示稍后重试；继续提供上次可用课表 |

## 验证与发布

本地验证包含真实 workerd DO 重启、取消前后发码阶段、重复 token、迟到成功/失败、QuickLogin 缓存换绑竞态、Workflow 重放与结束、课表恢复到成功和缓存保留。所有网络依赖以协议边界替身隔离；Python 测试运行真实 aiohttp 请求/取消/清理。

发布顺序：Auth 的 Worker、Workflow 和 Container 一起更新并确认 Container 版本健康，再发布 Schedule 的兼容重试策略与加法数据库迁移。Auth 使用 GitHub Actions；Schedule 使用现有 Cloudflare Git Connector，部署命令负责迁移。生产验收区分部署健康、Workflow 完成记录和真实课表同步，不用构建成功代替业务成功。

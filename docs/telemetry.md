# Telemetry v2

Production uses PostHog project 662666 through `https://p.cqu.moe`. Browser builds use `VITE_POSTHOG_PROJECT_TOKEN`; Worker/container runtime uses `POSTHOG_PROJECT_TOKEN`. These are public collection keys, not management API credentials. Local/test environments default off. Acceptance browsing may use `?telemetry_test=1` and is excluded from product dashboards.

Only explicitly allowed task properties leave the process. Credentials, names, email/student IDs, content, full URLs, raw errors, network bodies and console text are excluded. Authenticated identity is the central internal user ID; logout/account changes reset browser identity. Background work is marked separately from human use.

Owned production web pages use 100% masked replay while the existing free budget permits: inputs/text/attributes and media are masked or blocked; recorder network and console capture are off. School pages are outside the replay boundary. Browser transport preserves routing/session fields while stripping SDK initial person properties. Exceptions retain a bounded class, a fixed synthetic message and up to 50 allowlisted application frames (filename, function, line/column and source-map chunk ID). Python frames reference files under `container/`; web frames accept only Auth `/assets/*.js`; Worker frames accept only deployed bundle names. Absolute local paths, URL credentials/query/fragment, external scripts, source context, local variables and exception causes are excluded.

Business-error fingerprints use `auth:<surface>:<operation>:<error_code>:<class>`, excluding release and request/user IDs. This separates search, capture and other operations while preserving grouping across releases. Generic JavaScript exceptions without business labels use PostHog's stack-based grouping. An event's distinct ID is not a unique-person count for container/system operations.

Production `npm run deploy` builds and uploads web and Worker source maps to project 662666 before deploying those same injected bundles. `POSTHOG_CLI_API_KEY` is a build-only personal key with error-tracking write access; `POSTHOG_CLI_PROJECT_ID` must be 662666. The build host is `https://us.posthog.com`; SDK collection still uses `https://p.cqu.moe`. Web maps are removed before assets deploy. Worker maps are also uploaded to Cloudflare and are never static assets. Local/PR builds work without upload credentials. Existing stackless events cannot be repaired retroactively. Local tests, CI, deployment, observed events/replay and authenticated business acceptance are separate evidence.

Auth records request-level login/authorization/binding start and terminal states. MFA and continuation remain `needs_input`; session restoration is `app_session_ready`, not a new login. Browser-container operations report authoritative business outcomes separately from HTTP status. QuickLogin registration/reconcile responses add the central user ID without changing authorization, cookie ownership or task cancellation rules.

Validation before release: application/frontend tests, Worker types and contract/boundary checks, DO tests, Chromium container tests, frontend lint/design/build and real PostHog SDK serialization tests. Verify live ingestion separately after deployment.
